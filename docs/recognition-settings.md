# 识别参数云控

以下 Settings 字段可通过现有云控 settings 规则的 defaults / force 下发；离线仍使用本机缓存。

| 字段 | 默认值（保持原行为） | 云控范围 | 含义 |
| --- | --- | --- | --- |
| recheck_seconds | 5.0 | 1–60 秒 | 画面不变、已发布卡片的逐列复查周期 |
| pending_seconds | 0.9 | 0.1–5 秒 | 待确认读数持续超时后暂时隐藏该列 |
| low_match_reads | 3 | 1–10，严格整数 | 连续低命中的新 OCR 批次数达到阈值后，清掉内部稳定卡组 |
| active_hold_s | 5.0 | 0–30 秒 | 三选一关掉后保持快扫的时长，0 表示不额外保持 |
| idle_ocr_guard | false | 仅布尔 | 试用空闲像素检查，缺少标题信号时跳过部分OCR，周期复查；设置页没有开关，读设置时改回 false，只能云控打开 |
| fallback_first_s | 5.0 | 3–900 秒 | 1.1.7：这局还没认出过第一次海克斯选择时，整块兜底扫描的间隔；取 fallback_scan_s 和它的较小值，写 30 以上退回 1.1.6 |
| garbled_rescan_s | 3.0 | 1–600 秒 | 1.1.8：两次「读到半截名字」整块重扫之间至少隔几秒 |
| garbled_rescan_max | 10 | 0–100，严格整数 | 1.1.8：每局因半截名字整块重扫最多几次；0 = 不重扫（1.1.6 的做法）。这局认出过海克斯后不再因此重扫 |
| full_scan_gap_x | 4.0 | 0–20 | 1.1.8：兜底、半截名字的整块扫描之后，至少隔这次耗时 × 它才能再扫；0 = 不拉开（1.1.7 的做法） |
| auto_idle_factor | 5.0 | 0–20 | 1.1.7：空闲时标题条间隔 = 认字 CPU 时间 × 它（最长 1.2 秒）；0 = 按 idle_scan_ms（1.1.6 的做法） |
| vision_priority | below_normal | normal / below_normal / lowest | 1.1.8：识别线程优先级；lowest 是 1.1.7 的 |
| vision_eco | false | 仅布尔 | 1.1.8：识别线程开 Windows 效率模式（1.1.7 默认开，Intel 12～14 代大小核上认字慢 2～3 倍） |
| vision_no_throttle | false | 仅布尔 | 1.1.8：不开效率模式时明确不要降频（系统自己的后台降频也不要）；false = 交给系统，同 1.1.6 |

复查周期不允许 0，避免每轮强制重读或完全关闭复查；其余范围限制等待时间和连续确认次数。
布尔、字符串、非有限数、越界值忽略并按现有云控规则记日志；low_match_reads 不截断小数。
识别线程在每轮扫描前复制最新参数，不清除跟踪，不重建识别器。active_hold_s 在调度时直接读设置。
force 撤掉恢复原值，保存本机设置时不保存被 force 覆盖的值；defaults 遵守玩家自行修改的项。

默认值边界测试覆盖 5 秒复查、0.9 秒待确认超时、3 批真实 OCR 后清内部状态，以及 5 秒快扫保持。
沿用现有引擎连续三次读空后关闭标签的条件；low_match_reads 调的是识别器内部状态，不改变该条件。
颜色策略由 color_check 控制，本改动不增加“名字完全对上时信文字”的开关。

空闲降载的升级兼容、等待边界和验证限制见 [idle-recognition.md](idle-recognition.md)。

## 四选一（1.1.7）

测试服有张地图一次给四张海克斯。四张卡的卡距、卡宽和标题高度与三选一相同，整组仍以画面中线对称，只是错开半张：三选一卡心在中线和中线±1 个卡距，四选一在±0.5、±1.5 个卡距。所以按三选一定位的标题条只能读到相邻两张各半截名字，不会认出错位的卡。

- 整块扫描认出一排等距的四张，就按四张定位并存进 `calibration.json`（`boxes` 有 4 项；旧版读到会当无效位置重新定位）。只认到两三张时按卡心位置判断是哪种布局、在第几列；拿不准时按三选一原来的办法。
- 每局第一次认出之前，整块兜底按 `fallback_first_s`（默认 5 秒）扫，换地图后上一局的布局读不到卡，靠它换布局。标题条第一次认出但没认全时，再整块核对一次。
- 标题条至少两列读到清楚（置信度 0.8 以上、两个字以上）却对不上任何名字的字，连续两次，或第一次读到后持续 1 秒（卡片停稳后标题条走缓存不再读），就是定位框卡在两张卡之间：马上整块扫描重新定位，不等兜底间隔，两次之间至少隔 3 秒（1.1.8 起每局最多 10 次，认出过海克斯后不再重扫，见上表）。1.1.7-test.1 实录 4K：三张的定位读四选一读到「倒倒黄」「鼓声暴」，原来要等到下一次 5 秒兜底。认出后照旧按 `fallback_proven_s` 放慢。
- 4:3、5:4 这类窄屏，四选一最外侧的卡贴近画面边缘，整块扫描左右放宽；16:9 及更宽的屏幕扫描范围不变。
- 浮窗标签、主界面卡片、手动纠正和推荐文案（「四张都不理想」）都按实际卡数。
- 1.1.8：云控 `features.four_choice=false` 关掉四选一（一律按三选一认，也不做第一次认出后的核对），即 1.1.5 的认法。

### 三张、四张之间切换（1.2.0）

1.1.9 日志里看到两种情况：上一局四选一、这局三选一，整块扫描只认出两张时，张数改成了 3 张、标题位置还是 4 张，标题条每读一次报一次错，十几到半分钟后才恢复；四选一地图开局按三张的位置读到半截名字，要等整块扫描才切成四张，整块扫描慢的电脑（2560x1600 一次三四秒）要 9～30 秒，个别整组没给推荐。1.2.0：

- 张数和标题位置一起换。整块扫描数出的张数和定位不一样、但没认全（不能校准）时，标题位置马上按新张数排：卡距、框高沿用本机现有定位，整组以原来的中心对称，窄屏最外侧的框收窄到不出界。这份位置先不存，标题条认全后才写进 `calibration.json`。各列跟踪状态的长度和定位对不上时一律从头跟踪，不报错。
- 读到半截名字（判断同上）且这局还没认出过海克斯：先按另一种张数的位置读标题条，只多读一条窄带，不等整块扫描。认出两张以上就按这个张数走，认全后存下；那样也读到半截名字，换回原来的位置，马上整块扫描（同 1.1.8 的规则）；3 秒内没认出卡（多半是商店之类的字）也换回原来的位置。这局结束时还在试读的同样换回。
- 这局标题条第一次认出就没认全时，张数还没确认：先不出推荐，下一轮整块核对完再出（核对没找到卡就照常按标题条出）。最多晚一次整块扫描。
- 云控 `features.count_switch=false` 退回 1.1.9 的做法；各列长度对不上时从头跟踪这一条不受开关影响（只是不再报错）。
- 三张、四张的位置各存一份：`calibration.json` 加 `layouts`（`"3"`、`"4"` 各一份本机认出过的位置）；`boxes`、`size` 仍是最近认出的那份，1.1.9 及以前只读这两项。每局第一次认出之前，标题条每次没读到卡就换另一种张数的位置读，不等整块扫描；认出后这局不再换。另一种张数本机这个窗口大小上认出过就用存的那份，没认出过（没见过四选一）按三张的卡距推算（test.5 实录：推算的四张位置和后来整块扫描认出的差约千分之一屏宽），认全后存下；推算的位置兜底整块扫描照确认过的间隔。三选一的第一组平均最多晚半次标题条间隔（约 0.2 秒），读的次数不变。读到半截名字试读另一种张数时也直接用存的那份。1.2.0-test.5 实录（4K，整块扫描约 0.8 秒）：四选一地图第一组、下一局三选一第一组，标题条按上一局的位置读到半截名字，置信度不到 0.8，没触发上面的试读，等 5 秒兜底整块扫描，读到半截名字后约 3 秒才出推荐。云控 `features.layout_memory=false` 不轮流、只用最近那份（`layouts` 照样写）。

验证：合成画面（三种 16:9 分辨率和两种窄屏）跑真实 OCR；另用一张四选一实机截图（视频画面）核对整块扫描和标题条都认出四张。尚未在测试服实机上跑过。
