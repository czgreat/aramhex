# 游戏显示与性能排查

## 浮窗与截图的实际行为

游戏内右上角按钮和详情卡片是透明置顶窗口；海克斯推荐标签另有一个透明置顶窗口，只盖标签那一块。

| 项目 | 入口 | 对游戏画面上方窗口的影响 |
| --- | --- | --- |
| 游戏浮窗总开关 | 1.2.0 起没有玩家开关（托盘的“显示游戏浮窗”已去掉，以前关掉的读设置时打开）；云控 `force: {"overlay": false}` 可应急关闭 | 关掉后按钮、详情、标签都隐藏；后台截图和识别照常 |
| 对局中按需显示按钮 | 1.1.7 起固定开启，没有开关（云控可应急关闭） | 第一次海克斯选完 0.5 秒后，没有详情、没有海克斯选择时按钮窗口真正隐藏（不是透明度为零）；鼠标移到原位置附近再出现 |
| 详情的“背景”按钮 | 详情右下角，1.2.0 起，透明（默认）、半透明、不透明三档，点一下换下一档；设置页没有这一项 | 只改右上角详情面板的背景，三选一标签、装备提示、选英雄标注不变。Qt 把 8 位颜色读成 `#AARRGGBB`，1.1.9 起详情写的 `#101318ee` 实际是约 6% 的蓝色，几乎透明，「透明」保持这个样子；半透明约 70%、不透明 100%（`#101318`），会挡住后面的游戏画面。云控 `features.overlay_bg=false` 退回 1.1.9：按钮不显示，按透明画，玩家选的留着；云控设置 `overlay_bg`（`standard` / `dark` / `solid`）只能写在 defaults（改没选过的玩家的默认值），写在 force 里忽略 |
| “详情快捷键” | 设置页，1.1.7 起，默认不绑定；1.2.0 起默认不显示（云控 `features.overlay_hotkey`） | 只切换详情；用系统热键注册，不装键盘钩子，不影响显示 |
| 空闲时减少识别开销 | 设置页没有开关，默认关闭，只能云控打开 | 截图后少做部分 OCR，不改变浮窗和截图方式 |

1.1.7 起进对局到第一次海克斯选完之前，按钮一直显示（约游戏时间前 10 秒加读条），这段时间游戏上方有按钮窗口。

浮窗可以正常被截图和录屏。助手只在用于识别的截图里遮掉自己绘制的区域，避免认到自己的字；旧的“录屏、截图时显示浮窗”设置（`allow_capture`）1.1.1 已删除。截图用 mss 的 GDI 路径；DXGI 桌面复制试验分支在问题机器上没有改善，未合入。

## 识别占用的 CPU

识别只用 CPU（OCR 走 onnxruntime 的 CPU 推理，限定单线程；OpenCV 也限定单线程），不用显卡算。

- 识别线程（`engine._vision_loop`）：优先级低于正常（`THREAD_PRIORITY_BELOW_NORMAL`），不开 Windows 效率模式（EcoQoS）。1.1.7 曾改成最低一档并打开效率模式，Intel 第 12～14 代大小核电脑上每次认字的 CPU 时间涨到 2～3 倍、整块扫描从 3～6 秒变成 11～32 秒，1.1.8 改回。两项都能云控：`vision_priority`（`normal` / `below_normal` / `lowest`）、`vision_eco`（`true` 打开效率模式，系统不支持时日志写「未打开」）、`vision_no_throttle`（`true` 明确不要降频，Windows 自己的后台降频也不要；默认交给系统）；改了马上生效，日志写「识别线程：优先级…，效率模式…」。没用 `IDLE`：低配电脑上游戏占满所有核时，识别会一直排不上队。
- 判断是效率模式还是优先级：每局结束的「这局认字：标题条 N 次（平均 X 毫秒，CPU Y）」里，X ≈ Y 而 Y 比平时大，是线程被放到慢核或降频；X 远大于 Y，是排不上队（优先级）。日志开头「运行环境」一行写大小核（如 `P8+E16`，`否` 为只有一种核）。
- 标题条间隔：出现海克斯和关掉后 5 秒内按 `scan_interval_ms`（300 毫秒）；其余时间按这台电脑最近几次认字的 CPU 时间 × `auto_idle_factor`（默认 5，云控可改，0 = 按 `idle_scan_ms`，即 1.1.5 的做法）自动定（300～1200 毫秒），即空闲时识别线程最多占一个核的约五分之一。每局结束日志写「这局空闲时标题条间隔：自动 N 毫秒」。设置页的「识别频率」1.1.7 起去掉，`speed` 只留给云控。
- 一台 Ryzen 7 9800X3D、4K 的电脑实测：一局约 3.5 分钟，标题条认字 532 次，每次约 51 毫秒 CPU，约九成发生在没有海克斯的时候；合计约占一个逻辑核的 13%，16 线程的约 0.8%。按上面的规则这台电脑空闲间隔仍约 300 毫秒；同样的工作慢 3 倍的电脑空闲间隔约 0.75 秒。

## 整块扫描

标题条读不到时整块扫描整排重新定位，单线程，一次 1～6 秒（1.1.7 在受影响的大小核电脑上 10～37 秒），扫的时候读不了标题条。1.1.8 起：

- 读到半截名字（定位框卡在两张卡之间）时马上整块重扫，间隔 `garbled_rescan_s`（3 秒），每局最多 `garbled_rescan_max` 次（10，0 = 不重扫，即 1.1.5 的做法）；这局认出过海克斯后不再因此重扫。商店价格、装备名、属性碎片也会读成半截名字，1.1.7 不限次数，一局整块扫描从 1～4 次涨到 7～71 次。
- 兜底和半截名字两种整块扫描之间至少隔上次耗时 × `full_scan_gap_x`（4，0 = 不拉开）。
- 这局还没认出过时兜底间隔 `fallback_first_s`（5 秒），与 `fallback_scan_s`（30 秒）取小的；改成 30 即 1.1.5 的做法。
- 四选一：云控 `features.four_choice=false` 一律按三选一认，也不做第一次认出后的布局核对。
- 每局结束写「这局整块扫描：原因 次数 共几秒；半截名字没重扫：原因 次数；设置：…」。

以上设置都在 `lolhex/cloudsettings.py` 的 `SPEC` 里，云控 `settings` 规则的 `defaults` / `force` 可改。1.1.9 起另有一段 `settings_v2`，规则还能按电脑挑：`os`（`"10"` / `"11"`）、`hybrid`（大小核 `true` / `false`）、`vendor`（`intel` / `amd`）、`cpu`（型号片段）、`ids`（匿名编号），条件都满足后再按 `percent` 分组，例如只给 Win10 大小核的一半电脑改 `vision_priority`。1.1.8 及以前不读 `settings_v2`（只留认识的顶层段），所以条件只能写在这一段；写在 `settings` 里的条件规则 1.1.9 也整条跳过。`settings_v2` 每条都要写 `versions`，没写的整条跳过（免得以后的版本也被选中）；条件、`versions`、`percent` 格式不对的也整条跳过。对照试验用 `force`，`defaults` 写进设置文件、撤了也不改回。日志开头写「云控设置：本机命中规则 …（系统=… 大小核=… 厂商=…）」。

## 无边框下帧率封顶

无边框窗口模式下，游戏上方盖着透明置顶窗口时，Windows 可能不再让游戏独占翻转（Independent Flip），改由 DWM 合成画面，帧率常被限制在显示器刷新率附近。问题机器上的表现与此一致：浮窗显示时封顶，隐藏后恢复。

因此按需按钮的目标是让对局中大部分时间游戏上方没有助手窗口。按钮、详情或海克斯标签出现的那几秒仍可能封顶，后台截图和识别不受影响。

用 PresentMon（或 Intel PresentMon 图形界面）看游戏进程的 Present Mode 一列：`Hardware: Independent Flip` 为独占翻转，`Composed: Flip` 为 DWM 合成。下表各状态各记一次 Present Mode 和稳定后的 FPS。

## 对照方法

在同一台机器、同一场景，保持窗口模式、分辨率、刷新率、游戏帧率设置和其他浮窗软件状态一致。每次操作后切回游戏并确认游戏获得前台，避免把后台帧率限制混入结果。

| 状态 | 浮窗 | 助手截图与识别 | 用途 |
| --- | --- | --- | --- |
| 完全退出助手 | 无 | 停止 | 基线 |
| 正常运行助手 | 常驻按钮 | 运行 | 确认问题能重复出现 |
| 第一次海克斯选完后，鼠标远离按钮位置 | 隐藏 | 运行 | 按需按钮是否有效 |
| 云控强制关浮窗（1.2.0 起托盘没有这个开关） | 全部隐藏 | 运行 | 单独排除浮窗 |

若浮窗显示与隐藏来回切换能重复改变 Present Mode 或 FPS，问题在浮窗；隐藏后仍异常，再查截图和识别负载。黑闪、稳定封顶和团战瞬时掉帧分别记录，不默认是同一个原因。

性能对照先关闭调试：`debug.txt` 会额外保存选英雄和海克斯选择截图（测试包默认带 `debug.txt`）。
