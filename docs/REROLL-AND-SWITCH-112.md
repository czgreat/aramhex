# 1.1.2：单列刷新与切屏复核

## 已复现并修复的路径

使用原 Engine 循环、原 Detector 和模拟 OCR，在 VM197 复现：稳定三张后，一批 OCR 中两列失败，后两轮复用同一个缓存 None，也累计到三次失败，整组隐藏；随后整块兜底重校准并重读三列。单列失败仍有两列命中，会走已有逐列稳定逻辑；两列失败才会进入这里的低命中分支。真实用户每一次三框变化不一定都是这条路径。

修复保留内部稳定状态，低命中确认绕过空缓存，只对失败列作新 OCR；三批真实低命中才关闭，随后静态负画面停止 OCR。新卡仍须两次新识别确认。定期五秒复查一次最多一列，有变化先处理变化列，超过两倍复查周期时允许附带最老一列，避免动画长期占用。整块扫描恢复两张卡后也清除旧条带空缓存，下一轮重新观察。

## 切屏问题的边界

1.1.1 已有相同卡片更新坐标、整块/条带统一定位框、重校准清缓存；不是本轮新增修复。PR14 是缩小透明浮层以减轻双屏掉帧，不代表修好了单列左移。

本轮确定修复游戏退后台仍显示旧标签：与识别线程的前台判断一致，后台隐藏，回来恢复已有结果，不为每次 AltTab 强制昂贵全扫描。

中框持续左移尚无实际画面定因。可疑路径是整块 OCR 的中间文字框中心偏左并保存为校准，而至少两张仍能认出，自动兜底不触发。现有整组校准日志能提供三框坐标，但缺发生前后的画面。不要强制三列等距或取两端平均值，也不要声称后台隐藏已修复持续偏移。后续需要切屏前/后和手动重认后的截图、对应校准记录，验证长标题、特殊布局、分辨率与缩放。

## 独立复核与验证

独立子代理只读审查通过主要重试/错峰路径，指出两张卡全扫描恢复后的旧空缓存边缘问题，本轮补修及回归。另一个子代理复核历史定位修复与切屏问题，确认持续偏移不能定因。

初版 VM197 针对性 38 passed / 1 skipped，完整 315 passed / 4 skipped，exit 0；新增空缓存与后台隐藏测试、集成 PR13/14/15 后，针对性 68 passed / 1 skipped，完整 335 passed / 4 skipped，两项 exit 0。证据保存于工作区 artifacts/test-evidence-vm197/tests-integration-112-*.log；首次集成测试因诊断测试 fixture 缺 idle_scan_ms 失败，已补 fixture 并重跑。仅模拟 OCR 和 Qt offscreen；无真实 Windows 游戏、RapidOCR 模型性能验证。172 与 235 未测试，用户正在使用。原始日志 ZIP 保留于本次工作区 artifacts，不进入源码仓库。

## 本次 1.1.2 集成候选

本分支以 release-1.1.2 为基线，合入 PR13 查分不可见字符、PR14 缩小透明浮层（含后续默认 idle_scan_ms=300 修正）、PR15 诊断，以及本次刷新连续性/后台隐藏。原 PR 保留供逐项审阅，集成候选不意味着已合入正式发布分支。合并诊断时 Detector 外层缓存条件保留 `not confirming` 与 `strip_cache` 计数；两个测试 fixture 补 `idle_scan_ms=300`。

不包含：1.1.3 的召唤师技能变更（PR12）、已撤回的全扫描退避、卡框/按钮作为 OCR 前置门、未经实测的模型/线程优化、中列强制等距、AltTab 强制整块重扫。单次整块 OCR 多秒的问题仍待真实模型与分段日志验证。

## 172 开启 Debug 后的新增证据与防护

172 安装版 1.1.1 原未开启 Debug。经用户授权，在 `%APPDATA%/AramHex/debug.txt` 建立空标记，只重启助手并以 `--minimized` 启动；2026-10-24 18:06:27 日志确认调试模式启用，已得到五张新自动截图。未升级本机安装版、未切换游戏设置或主动切走游戏。原始截图、前后日志及校准以 SHA-256 清单保存在工作区 `artifacts/local172-debug-20261024/original-local172-debug.zip`，不进源码库。

旧 INFO 日志已记录今天 17:34:28 的异常校准：3840x2160 下中框中心约1459，17:42:57恢复后约1921，差约462像素；左中裁剪框重叠约339像素。异常保存后出现中右同为王冠之重、下一条左中同为缩小引擎。这是本机真实坏校准证据，尚不能证明 AltTab 是触发源。

将历史框中心作为模拟 OCR 几何输入，在 VM197 回放同一 `_scan_full` 路径：修复前测试失败，旧代码实际发布并保存重叠框；修复后拒绝该结果，原有效校准、文件字节和低命中计数不变。测试分别从各自源码目录运行，避免 pytest 导入修复版造成假基线。该回放证明坏几何接受路径，不代表已用真实 OCR/AltTab 端到端复现。

新防护拒绝现有算法生成的重叠裁剪框，不新增固定等距判断；同时拒绝非有限尺寸/坐标、越界、反向及量化后零面积区域。加载已有坏校准时不使用它，留原件供取证，默认位置随后接管，直到有效三框替换。极端不等距布局仍可能因现有裁剪宽度而被拒绝，需要真实特殊布局继续验证。拒绝日志每60秒最多一条，不改变扫描间隔。

复现优先级：先用该历史几何确定性回放；再使用 Debug 实际截图与日志，对比下一次异常前后校准、窗口客户区与浮层坐标，分别排查文字片段/遮挡、淡入动画、AltTab前后台、窗口位置/分辨率/DPI变化。当前自动截图按卡片内容变化触发，单纯坐标变化可能漏截；因此 Debug 不等于完整切屏轨迹。不要要求用户盲目等偶发，也不要自动接管正在进行的对局切屏。
