## 当前范围

独立复核后，PR #15 **撤回自动延长整块扫描间隔**，恢复 release-1.1.2 基线调度；FullScanBudget 及对应测试已移除。当前只补诊断，不引入按钮/卡框阻断、不换模型、不改变匹配及稳定确认规则，也没有修复同步推理本身。

撤回原因：15 秒推理后再冷却 60 秒虽然减少后台计算，但标题位置不适用、只能依赖整块定位的布局可能更晚发现卡片。减少计算量不能直接当作玩家看到提示更快。

## 当前诊断实现

- 启动 INFO 补 CPU 型号、逻辑核、Windows 可用/总内存、系统和识别设置；OCR 初始化记录库版本、实际会话线程和 provider。没有主机名、序列号或账号。
- 每次走原有截图路径时分配进程内扫描编号并测截图与工作阶段，区分 full/strip、titles/fallback/bootstrap/manual 来源，无新增截图调用。慢扫描按路径各自每分钟最多一条；截图失败明确归 capture 而非 work，原异常继续抛出。
- OCR 包装对整块和标题分别记录慢调用总耗时、锁等待、模型上报检测/认字时间、尺寸和文本行数，每类每分钟最多一条。elapse_list 遵循 [RapidOCR 3.9.2 文档](https://rapidai.github.io/RapidOCRDocs/v3.9.2/install_usage/rapidocr/usage/)，缺失/非法写 unknown。
- 后续独立策略复核确认，仅认字返回 TextRecOutput.elapse 而非 elapse_list，已补兼容；启动再补模型族/大小/语言、检测缩放配置和 Rec 批形状。配置值不等于实际每次模型张量尺寸。
- 新卡组更新内部推荐状态后记录扫描编号、来源、观察编号、截图/工作/工作后至发布及取图后年龄。同卡组重复轮询不刷发布日志；trace 不写入 UI 状态。
- 每局汇总全域文本行、字典命中、条带缓存、标题未匹配、颜色拒绝和待确认列观察数。计数不参与决策，对局结束重置。

“推荐状态发布”是内部状态更新，**不是 UI 已绘制，也不是卡片真实出现到提示的延迟**。frame_age 从截图调用返回计起，无法代表精确采集瞬间；source=cache 时也不能当作原 OCR 结果年龄。标题未匹配可能只是无卡或空文字，不能算故障；pending 按列累计，不是独立扫描次数。work 包含检测器全部计算，模型分段日志进一步拆解；异常时仍保留原堆栈。

原有 INFO 会记录选卡推荐；新增性能诊断不额外记录 OCR 原文、图像、账号或本地路径。旧版云控点名不能远程补出新版字段或截图。

## 验证及剩余工作

上一版诊断在当时空闲的 VM197 Ubuntu 独立目录测试：针对性 35 passed / 1 skipped，完整 312 passed / 4 skipped。补 TextRecOutput 兼容后的当前版本针对性 36 passed / 1 skipped、退出成功；完整套件两次均输出 313 passed / 4 skipped，但解释器退出阶段发生 Segmentation fault、退出码 139，不能视为干净通过。同环境未改基线对照也输出 301 passed / 4 skipped 后退出 139，说明当前环境/基线也能复现，不能将崩溃单独归因于此改动；具体原生原因仍未确定，PR 继续草稿。Python 3.14.4、Qt 6.12.0、numpy 2.5.4，与生产 Windows Python 3.13 / Qt 6.11.2 / numpy 2.5.3 不同；未安装 RapidOCR/ONNX 模型，没有真实推理或游戏性能实测。本机和 235 未用于测试。

回归覆盖原扫描间隔、在途同步调用边界、截图/模型异常归属、两类限频独立、结果不变、发布不重复、trace 不进 UI 及不记录 OCR 原文。第二次独立审查发现截图失败计时归属问题，已修正并加回归。

同步 OCR 的过期截图发布风险尚未修复，应通过真实回放验证采集/窗口/会话版本和丢弃策略，避免固定超时让慢机器永远不出结果。按钮/卡框先做旁路计数，再测国服棱彩、遮挡、刷新、隐藏展开、未校准与缩放。需要真实出现/刷新/消失标注，才能比较首次提示和尾部延迟。
