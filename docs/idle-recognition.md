# 空闲识别降载试用

本功能默认关闭。1.1.7 测试包的设置页曾有“空闲时减少识别开销（试用）”勾选框，1.1.7 正式版去掉了：省下的只是部分 OCR，不解决无边框锁帧，玩家也无从判断该不该开。用一台 4K 电脑的 24 张实际对局截图，在卡片以外的游戏画面上放 384 个标题大小的框，只有 47% 判成没字；要三、四个框同时没字才跳过一次，大乱斗冰雪地面偏亮，实际能跳过的约一两成，还要每秒至少认一次。空闲时省 CPU 改由按本机认字耗时自动放慢标题条（见 [游戏显示与性能排查](display-performance.md)）。测试包里勾过的，读设置时改回关闭。现在只能经云控 `defaults` / `force` 小范围打开。尚未完成低配和 Windows 10 实机性能验证。

## 行为

游戏背景不断变化，即使没有三选一，也可能使标题指纹变化并触发 OCR。试用开关开启后，只在已有本机确认校准、没有卡组和待确认结果时检查已有标题截图的像素。

任一标题区域出现少量可能的亮色字形信号就继续正常识别。三个区域都缺少信号时，可以省去这一次认字。这不等于确定“没有卡片”：距上次读字完成满 1 秒后，下一次正常扫描仍回到原识别路径；原有指纹缓存可能进一步免去相同画面的重复识别。标准300ms调度下，该周期边界通常落在1.2秒扫描点；空闲间隔自动放慢、系统繁忙时沿用自身调度，不承诺1秒的绝对响应上限。

首次扫描、移动窗口、校准未知、部分区域被裁切、输入格式未知、像素检查异常时均继续原识别。已有卡组、单列刷新确认、整组换牌确认不经过省略路径。全域定位、手动重扫、原有兜底频率不变。像素不能识别海克斯身份，也不用于拒绝某种稀有度。

实现使用现有 NumPy，不增加第三方代码、训练模型、DLL、系统接口或下载。主程序许可证和原依赖声明保持不变。

这项检查发生在截图之后，只减少部分 OCR 工作，不减少截图调用，也不改变浮窗窗口属性。它不能据此宣称修复无边框锁帧、黑闪或浮窗与截图的显示兼容问题；这些需要按 [游戏显示与性能排查](display-performance.md) 单独验证。

## 升级及回退

- 仅增加布尔设置 `idle_ocr_guard`，默认 `false`。读设置时一律改为 `false` 并从 `user_set` 去掉。
- 设置路径、`calibration.json` 结构、统计数据结构及更新清单结构不变，已有设置、校准和未知配置键保留。
- `requirements.txt`、`requirements-build.txt`、打包与增量更新实现不变。本改动没有增加需要完整重装的运行库；最终发行产物仍须按既有发布流程检验文件清单与升级。
- 可经原云控设置 `defaults` 小范围试用，也可 `force: {"idle_ocr_guard": false}` 临时关闭；撤销后恢复关闭。
- 对局日志记录像素检查次数、跳过读字次数和检查异常次数，不新增截图、账号或识别文字采集。

## 验证及边界

本机9张历史真实选卡截图，经居中裁切或补边生成5种窗口尺寸，共45次像素检查，全部放行到正常识别。尺寸包括1024×768、1920×1080、2560×1440、3440×1440、3840×2160。这些是9张图的变换，不能当作45个独立实机样本，也不是实测DPI变化。原始截图含对局信息，不加入仓库。

开发机上45组检查耗时的中位数约0.64ms，最慢组p95约2.53ms，仅代表本次输入与机器。60秒、200个调度点的合成暗色背景计数中，OCR调用从600次降到120次；这是调用计数实验，不是低配CPU、内存或游戏帧率收益。

自动测试覆盖首次放行、低信号跳过、有信号立即恢复、周期兜底、慢OCR完成后计时、待确认/换牌不省略、窗口变化、异常回退、旧设置/校准读取、UI保存及云控撤销。已有识别、会话切换、设置和更新回归独立运行。

仍需补充正常对局无卡录像、不同品质/淡入动画、界面缩放、遮挡及低配实机观察。深色文字、异常滤镜或标题信号很弱时可能延后到周期复查。因为还缺这些证据，默认不启用。
